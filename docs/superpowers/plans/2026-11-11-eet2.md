# EET 2.0 (fáze 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two Odoo 18 modules in `elite_common` that register every paid POS order of an EET-enabled till in EET 2.0 at payment, keep unsent sales in a retried queue, and offer batch resend, connection check and certificate expiry warnings.

**Architecture:** `elite_eet` holds a pure-Python package `elite_eet/eet/` (formatting, message build + XSD, WS-Security signing, transport, response parsing, certificate reading) with no Odoo imports, plus the models `elite.eet.device`, `elite.eet.sale`, `elite.eet.attempt`, crons and the batch action. `elite_eet_pos` creates `elite.eet.sale` from POS orders synced from the till screen (`pos.order.sync_from_ui` → `_process_saved_order`) and sends it after commit. One entry point, `elite.eet.sale._eet_send()`, is the only place that turns sales into messages, so a future batch interface replaces just that method and `eet/transport.py`.

**Tech Stack:** Odoo 18 (Docker `odoo:18`, Postgres 16), Python 3.12, lxml 5.2.1 (exc-c14n, XSD), cryptography 41.0.7 (PKCS#12, RSA-SHA256), requests 2.31.0.

**Spec:** `docs/superpowers/specs/2026-11-11-eet2-design.md` (approved 2026-11-11). Official sources are in the session scratchpad `…/scratchpad/eet/docs/` and `…/scratchpad/eet/zip/playground/`; Task 1 copies what the modules need into the repo.

**Scope of this plan:** phase 1 of the spec. Certificate *renewal* through the CA EET API is phase 2 and gets its own plan; phase 1 has expiry watch and warnings only.

## Global Constraints

- Odoo 18, `"license": "LGPL-3"`, `"author": "Michal Varys"`, `"website": "https://www.michalvarys.eu"`, version `18.0.1.0.0`; README in Czech, code comments in English (match `elite_common/elite_pos_l10n_cs`).
- No new Python dependencies. Exclusive C14N via lxml, signing via cryptography.
- No demo data in either module; no `demo` key in manifests. Modules change nothing for companies and tills without an enabled EET device.
- Production URL `https://trzbyeet.gov.cz/eet/services/EETServiceSOAP/v4` is used only by a device with `environment == 'production'`; Playground `https://pg.trzbyeet.gov.cz/eet/services/EETServiceSOAP/v4`. Under the test runner a production URL raises.
- SOAPAction `http://fs.gov.cz/eet/OdeslaniTrzby`, `Content-Type: text/xml; charset=utf-8`, namespace `http://fs.gov.cz/eet/schema/v4`, message ≤ 12 kB (12 288 bytes) including envelope, ASCII 32–126 only.
- Amount pattern `((0|-?[1-9]\d{0,7})\.\d\d|-0\.(0[1-9]|[1-9]\d))`; `id_pokl` `[0-9a-zA-Z.,:;/#\-_ ]{1,20}`; `porad_cis` same charset `{1,25}`; `id_jednotky` `[1-9][0-9]{0,8}`; EIČ `CZ[0-9]{8,10}`; dates `YYYY-MM-DDThh:mm:ss+01:00|+02:00` in Europe/Prague.
- Response timeout default 3 s, minimum 2 s. Resend deadline = `dat_trzby + 48 h`.
- Certificate password and private key never appear in logs, chatter, attempt records or fields readable outside `base.group_system`.
- Sending never runs inside the transaction that saves the POS order.

## Review Focus

1. **Order synced late (till was offline):** `prvni_zaslani` must be `false` when the order reaches the server more than 5 minutes after `date_order`. Test in Task 9.
2. **EET down during a cron run:** after the first `no_response` for a device, the cron must skip that device's remaining sales in the same run instead of waiting 50 × timeout. Test in Task 7.
3. **Diacritics and odd characters** in till name or order name (`Pokladna Bar č. 1`, `Arena/0001 REFUND`) must become valid `id_pokl` / `porad_cis`, not an XSD error 3. Tests in Tasks 2 and 9.
4. **Summer vs winter time and the DST switch:** `dat_trzby` offset must be `+02:00` on 2027-07-01 and `+01:00` on 2027-01-15, and correct for 2027-03-28 01:30 UTC. Test in Task 2.
5. **Cash change line:** paying 1000 Kč cash for 250 Kč produces a `-750` change payment; `celk_trzba` must be `250.00`. Test in Task 9.

### Task 4: Message build, XSD check, WS-Security signature

**Files:**
- Create: `elite_common/elite_eet/eet/message.py`, `elite_common/elite_eet/eet/wssec.py`
- Test: `elite_common/elite_eet/tests/test_message.py`, `elite_common/elite_eet/tests/test_wssec.py`

**Interfaces:**
- Consumes: Task 2 formatters, Task 3 `load_p12`, `paths.SCHEMA_XSD`.
- Produces:
  - `@dataclass class SaleData: eic_popl: str; id_jednotky: str; id_pokl: str; porad_cis: str; dat_trzby: datetime; celk_trzba: Decimal | float; urceno_cerp_zuct: float | None = None; cerp_zuct: float | None = None`
  - `class MessageError(Exception)`
  - `build_trzba(data: SaleData, uuid: str, sent_at: datetime, first: bool, verification: bool) -> lxml Element` — `v4:Trzba` with `Hlavicka(uuid_zpravy, dat_odesl, prvni_zaslani, overeni)` and `Data` with only non-empty attributes; optional voucher amounts omitted when `None` or zero; validates against the XSD (`MessageError` with the schema's error text).
  - `sign_envelope(trzba: Element, private_key, certificate) -> bytes` in `wssec.py` — returns the serialized SOAP envelope; raises `MessageError` if over 12 288 bytes.
  - `verify_envelope(xml: bytes) -> bool` in `wssec.py` — recomputes the Body digest and checks the RSA-SHA256 signature with the certificate from `BinarySecurityToken`.
- Signing algorithm (fixed by the GFŘ samples, which the tests verify):
  1. Envelope `soapenv:Envelope` declaring `soapenv` and `v4`; `soapenv:Header/wsse:Security` declaring `wsse` and `wsu`; `soapenv:Body` with `wsu:Id="id-<hex>"` and its own `xmlns:wsu`.
  2. `wsse:BinarySecurityToken` (`EncodingType …#Base64Binary`, `ValueType …#X509v3`, `wsu:Id="X509-<hex>"`) = base64 DER certificate.
  3. Digest: SHA-256 of `etree.tostring(body, method="c14n", exclusive=True, inclusive_ns_prefixes=["v4"])`, computed after the Body is attached to the final tree.
  4. `ds:SignedInfo`: CanonicalizationMethod exc-c14n with `ec:InclusiveNamespaces PrefixList="soapenv v4"`, SignatureMethod `http://www.w3.org/2001/04/xmldsig-more#rsa-sha256`, one Reference to `#id-<hex>` with Transform exc-c14n `PrefixList="v4"` and DigestMethod `http://www.w3.org/2001/04/xmlenc#sha256`.
  5. SignatureValue: PKCS1v15 SHA-256 over exc-c14n of `SignedInfo` (inclusive prefixes `soapenv`, `v4`), after it is attached in the final tree.
  6. `ds:KeyInfo/wsse:SecurityTokenReference/wsse:Reference URI="#X509-<hex>"` with the X509v3 ValueType. No Timestamp, no WS-Addressing.
  7. Serialize without XML declaration, no pretty print.

  - `elite.eet.sale._eet_send(first_send: bool | None = None) -> dict[int, str]` — **the single sending entry point**. Locks rows with `SELECT id FROM elite_eet_sale WHERE id IN %s AND state != 'registered' FOR UPDATE SKIP LOCKED`; for each locked sale: `first_send` defaults to `not sale.attempt_ids`; builds `SaleData`, new `uuid4`, signs, `transport.send(device._eet_url(), …, device.response_timeout)`, stores an attempt; state: `pok` → `registered` (+`pok`, `received_at`, `is_test`, warnings); `temporary`/`no_response` → stays `pending`; `critical` → `error` and `last_error`; `MessageError` → attempt `local_error`, state `error`. Returns `{sale_id: attempt.result}`. Skips sales whose device is not `active_eet`.
  - `elite.eet.sale._eet_send_after_commit(first_send: bool | None = None)` — registers `self.env.cr.postcommit.add(...)` that opens `self.env.registry.cursor()`, calls `_eet_send(first_send)` on the ids and commits; exceptions are logged (no password, no XML) and swallowed.
  - `elite.eet.sale._cron_send_pending(limit: int = 50)` — pending sales of active devices ordered by `dat_trzby`; per device, after the first `no_response` skip that device's remaining sales in this run; commit after each sale when not testing (`if not modules.module.current_test`).
  - `elite.eet.sale.action_send_to_eet()` — list action for `group_eet_manager`: sends selected `pending` and `error` sales with `first_send=False`, skips `registered`, returns a `display_notification` „Odesláno X, evidováno Y, chyba Z, přeskočeno W“.
